# File Explorer Depth Controls 功能需求说明书

## 1. 文档概述与产品定位

本说明书记录 v1.0.0 的当前实现，供项目负责人审阅。产品面向目录层级较深的 Obsidian 库，提供三个常见操作入口：文件目录顶部按钮、命令面板或快捷键、插件设置页。用户可以快速把原生目录树收至指定层级、全部展开，或者在浏览目录结构时保留当前笔记的路径。

设计沿用原生文件目录及其折叠状态，多个文件目录视图共享插件选定的层级。界面优先使用宿主组件、主题变量和可访问性属性。插件支持桌面端、iOS 和 Android，清单声明最低版本为 Obsidian 1.8.7。公开版只负责目录视图收展及偏好设置，范围不包含目录计数、文件夹右键菜单、笔记编辑或同步。

## 2. 整体架构与模块职责

| 位置 | 职责 |
| --- | --- |
| `src/main.ts` | 加载和持久化偏好，管理插件生命周期、工作区事件、命令、工具栏、任务队列、启动恢复和提示。 |
| `src/depth.ts` | 定义层级类型与范围，计算目录深度、祖先集合、步进目标、上限约束和折叠执行顺序。 |
| `src/explorer.ts` | 定位工具栏挂载点，提取原生目录项，应用收展、刷新目录树并核验结果。 |
| `src/settings-data.ts` | 定义偏好和默认值，验证已保存的数据，兼容早期用 `level` 保存当前层级的数据。 |
| `src/settings.ts` | 生成设置项和组件，处理用户变更、下拉框刷新和语言切换后的页面更新。 |
| `src/i18n.ts`、`src/locales/en.ts`、`src/locales/zh.ts` | 解析插件语言模式并供应统一结构的英文和简体中文文案。 |
| `styles.css` | 定义按钮排布、折行、高亮、焦点和禁用样式。颜色、字号和间距沿用 Obsidian 主题变量。 |
| `tests/` | 验证层级算法、原生视图适配和语言解析。 |
| `manifest.json`、`versions.json`、`esbuild.config.mjs`、`.github/workflows/release.yml` | 声明版本和兼容性，生成生产包，校验标签并创建草稿发布。 |

插件加载时调用 `loadData()`，验证偏好后解析界面语言、注册命令与设置页，并监听工作区布局和活动视图变化。布局就绪后同步工具栏，并按偏好安排启动恢复。按钮和命令先执行收展，所有目标视图校验成功后再保存新层级；设置页先保存用户选择，需要时再应用收展。偏好变化通过 `saveData()` 持久化，工具栏与设置页读取同一份内存偏好。

## 3. 详细功能需求

### 3.1 层级规则与当前笔记保护

库根目录记为深度 0，库根下的文件夹为深度 1。选中 `Ln` 时，深度小于 `n` 的目录展开，深度大于等于 `n` 的目录折叠。因此 `L1` 下库根内容仍可见，顶层文件夹默认处于折叠状态。`All` 展开所有目录项，展开深度不受 `L6` 或工具栏上限约束。

开启「保持当前文件可见」时，每次应用数字层级都会从当前活动文件路径提取完整的父目录集合，并对这些目录应用展开规则。假设活动笔记为 `项目/规划/草稿.md`，切到 `L1` 时会保留 `项目` 和 `项目/规划` 展开，同级目录仍按 `L1` 折叠。根目录笔记没有父目录例外，未取得活动文件时按普通规则收展。插件在应用层级时读取活动文件。单独切换笔记只会触发工具栏同步，目录收展规则在下次应用层级时重新计算。

每个视图内先按深度从深到浅折叠，再从浅到深展开。仅对状态需要变化的目录项调用原生收展，递归参数设为 `false`。完成后调用可用的原生树刷新和折叠保存钩子，再按同一规则重新校验目录项，当前笔记的父目录也参与校验。

### 3.2 顶部工具栏与多视图

工具栏挂载在原生文件目录顶部操作区域。默认显示 `L1`–`L4` 及「全部」或 `All`。层级上限变化后，所有已挂载工具栏按新范围重建。多个已打开的文件目录视图共用当前选中层级，一次收展请求会处理工作区中的目标文件目录视图。布局变化可为新出现的视图挂载工具栏，关闭视图后移除对应工具栏。

当前层级用 `is-active` 和 `aria-pressed` 标识。按钮提供本地化的悬停文案及无障碍名称。操作执行时暂时禁用按钮。关闭工具栏会移除组件和点击监听，命令与用户绑定的快捷键仍可用。隐藏「全部」按钮后，仍可用当前层级下拉框、直达命令或步进进入全展开状态；处于 `All` 时，工具栏无选中的数字按钮。

工具栏挂载时在原生宿主上添加专属类名，以支持旧版 Android WebView 的折行布局。移除工具栏时同步清理类名。移动端按钮最小宽高均为 36 CSS 像素，按钮留有间距并提供按压反馈，宽度不足时自动折行。悬停样式仅在主要输入设备支持悬停时启用。

### 3.3 命令面板与快捷键

| 命令 ID | 行为 |
| --- | --- |
| `show-depth-1` 至 `show-depth-6` | 直达指定层级。若目标高于当前工具栏上限，收展成功后将上限自动提高到目标值。 |
| `expand-all` | 切换至 `All`，不改变工具栏上限。 |
| `depth-deeper` | 数字层级内递增。达到上限后再加深进入 `All`，已在 `All` 时保持 `All`。 |
| `depth-shallower` | 数字层级内递减。从 `All` 回到当前上限，已在 `L1` 时保持 `L1`。 |

Obsidian 命令面板显示当前语言的命令名称。用户可在 Obsidian 快捷键设置中为命令分配按键，插件不预设按键。切换语言时重新注册的命令继续使用原命令 ID。

### 3.4 启动恢复

默认在工作区布局就绪后尝试应用上次保存的层级，首次使用按默认 `L3`。每轮恢复最多尝试五次，首次排队延迟为 0 毫秒，后续四次分别在前次未成功后等待 100、250、500、1000 毫秒。实际执行也受队列和视图加载时间影响。自动恢复不显示成功提示，找不到文件目录视图时不提示，其他失败在当轮最后一次仍失败时提示。

若本轮未成功，恢复转为等待事件，不再定时重试。打开手机左侧抽屉时，首次出现或重新挂载的目录宿主会唤起新一轮恢复。宿主已在页面上时，支持 `IntersectionObserver` 的移动端还会在其进入可见区域时唤起恢复。定时器或恢复任务已有安排时合并触发，避免并行执行。该机制也适用于隐藏工具栏的情况。

手动点击工具栏、触发层级命令或更改任一插件设置时，会取消本次尚待执行的自动恢复，释放移动端可见性监听。正在等待原生收展调用的恢复任务会在调用返回后的下一处检查停止。单独切换语言不执行目录收展。

### 3.5 设置项与默认值

| 设置项 | 偏好字段 | 默认值 | 生效规则 |
| --- | --- | --- | --- |
| 语言 | `language` | `auto`，跟随 Obsidian | 可选跟随、简体中文、English，保存后续加载用的语言模式，同时热刷新插件界面。 |
| 启动时恢复上次层级 | `restoreOnStartup` | 开启 | 关闭时取消当前待恢复任务；打开后用于下次插件加载。 |
| 当前显示层级 | `depth` | `L3` | 可选 `L1` 至工具栏上限及 `All`，选择后保存并尝试应用。 |
| 工具栏最大层级 | `maxDepth` | `L4` | 可选 `L2`–`L6`，同时更新工具栏和层级候选项。若当前数字层级超过新上限，降至上限并尝试应用，`All` 保持原值。 |
| 显示「全部」按钮 | `showExpandAllButton` | 开启 | 立即增减工具栏上的 `All` 按钮。 |
| 保持当前文件可见 | `keepActiveFileVisible` | 开启 | 变更后尝试重新应用当前层级，数字层级按新偏好决定是否保留活动文件的父目录。 |
| 显示目录顶部工具栏 | `showToolbar` | 开启 | 立即挂载或移除所有可用视图的工具栏。 |
| 切换层级成功时显示提示 | `showNotices` | 关闭 | 控制手动层级操作成功提示。错误通知和主动指定层级时缺少文件目录的提示独立显示。 |

旧偏好缺少 `language` 或值无效时回退至 `auto`。旧数据缺少 `depth` 时可读取数字字段 `level`；无效层级或其他字段按默认值校正。数字层级受有效工具栏上限约束。

### 3.6 双语解析与热刷新

「语言」位于设置页第一项。`auto` 通过 Obsidian 的 `getLanguage()` 取得语言标签，`zh` 及后接连字符、下划线的变体匹配简体中文文案，其余语言回退至英文。`zh` 与 `en` 分别固定使用简体中文与英文。该偏好只影响插件，Obsidian 自身语言由宿主设置管理。

变更语言后，插件更新文案来源，重建所有可挂载工具栏，更新「全部」按钮、按钮悬停标题和无障碍名称。设置项名称、说明和选项随设置页刷新，旧下拉框引用会清理。Obsidian 提供 `update()` 时通过它更新声明式设置，早期版本在该页可见时走原有绘制逻辑。

插件用同一组 ID 注销并重新注册命令，更新命令面板名称。宿主若没有 `removeCommand()`，保留现有命令注册以避免重复，重新加载插件后按保存的语言生成名称。随后产生的提示使用新文案。发布清单中的插件名称与版本保持固定。

## 4. 异常场景、并发与边界

| 场景 | 当前处理 |
| --- | --- |
| 视图尚未加载 | 按需等待 `loadIfDeferred()`；延迟加载完成后重新取视图。就绪视图数量与请求开始时不符时按未就绪处理。 |
| 有目录但目录项未就绪 | 读取不到目录项，或库中已有文件夹但原生视图尚无任何文件夹条目时，报告未就绪。无文件夹的库可正常执行空操作。 |
| 内部接口不兼容 | 适配层接受对象或 `Map` 形式的 `fileItems`。检查目录项的折叠状态与原生收展方法，跳过文件和根目录。不支持的接口有明确错误提示。 |
| 工具栏挂载点缺失 | 先找原生头部操作区，再尝试容器内的备用选择器。两者都缺失时跳过该视图的工具栏，后续工作区事件会再次检查。 |
| 状态校验失败 | 提示部分目录未达到目标。已执行的原生折叠没有回滚。按钮或命令请求失败时保留此前选定的层级，直接修改设置时保留用户已选择的偏好。 |
| 偏好保存失败 | 提示保存失败，当次内存状态继续生效。 |
| 连续操作 | 设置变更、启动恢复和目录收展共用串行队列。等待或执行中禁用工具栏，已有交互任务待处理时忽略后续手动层级命令，避免重复操作。 |
| 停用或卸载 | 清除恢复定时器和可见性监听，移除工具栏、宿主类名和点击监听。已注册的工作区事件和命令由 Obsidian 插件生命周期回收。待执行任务会检查卸载状态，并跳过后续的视图操作。 |

## 5. 非功能需求与社区上架检查

- **兼容性**：公开清单允许桌面端、iOS 和 Android 加载，最低 Obsidian 1.8.7，`versions.json` 对应同一版本。设置页同时支持声明式接口和早期绘制入口。`file-explorer` 的内部结构可能随 Obsidian 更新变化，适配层负责校验和降级。
- **性能与可访问性**：文件目录工具栏依靠布局及活动视图事件同步，启动重试有次数限制。应用层级仅收展状态不同的目录项。工具栏可折行，颜色取主题变量，按钮支持键盘焦点并公开按压状态。
- **隐私**：运行时无需网络或遥测。仅通过插件设置 API 保存配置，折叠状态交由 Obsidian 原生文件目录保存。插件不编辑、创建或删除笔记，也不写运行状态日志。
- **清单与命令**：公开插件 ID 为 `file-explorer-depth-controls`，名称和英文描述与清单一致。命令 ID 不重复加插件前缀，UI 使用本地化文案和 Obsidian 组件，代码不通过 `innerHTML` 插入内容。仓库采用 MIT 许可。
- **构建与测试**：执行 `npm run typecheck`、`npm run lint`、`npm test`、`npm run build`。ESLint 含 Obsidian 插件规则并以零警告为门槛。测试覆盖层级、收展顺序、路径保护、异常适配和语言模式。生产入口由 esbuild 生成 `main.js`；草稿 Release 上传 `main.js`、`manifest.json` 和 `styles.css`。`versions.json` 位于仓库根目录。本文档不参与构建或发布打包。
- **人工验收**：检查中英文切换、多视图同步、桌面窄侧栏和明暗主题。在 iOS 和 Android 上分别检查窄屏折行、触控反馈，以及冷启动后延迟打开文件抽屉时的恢复行为。完成检查后再提交社区审核。
